00三大件概念总览：IPMI · BMC · ipmitool

IPMI（协议）

Intelligent Platform Management Interface，智能平台管理接口。它是 Intel 牵头制定的一套硬件管理协议标准，定义了管理控制器与系统硬件之间交换信息的报文格式、命令集与事件机制。当前主流版本为 IPMI 2.0（2004 年发布，引入 RMCP+ 加密、SOL、VLAN）。

BMC（硬件）

Baseboard Management Controller，基板管理控制器。它是主板上的一颗独立芯片（常见 ASPEED AST2500/AST2600、Nuvoton），拥有独立 CPU、内存、网络栈与固件。主机关机甚至 CPU 损坏时，BMC 依然工作——这就是"带外管理"的物理基础。

ipmitool（工具）

Linux 下最通用的 IPMI 命令行客户端。它既可以通过内核驱动（/dev/ipmi0）与本机 BMC 通信，也可以通过 LAN 走 RMCP/RMCP+ 协议（UDP 623 端口）管理远程服务器。同类工具还有 freeipmi、OpenIPMI，但 ipmitool 生态最广。

带内 vs 带外：SSH/远程桌面依赖操作系统运行，属于"带内"；IPMI 直连 BMC 芯片，操作系统崩溃、蓝屏、断电状态下仍可开关机、看传感器、读日志，属于"带外"。KVM over IP（远程画面）虽然也由 BMC 提供，但它不是 IPMI 协议的一部分，而是各厂商的私有实现。

01IPMI 架构与核心名词

1.1 系统架构图

图 1 · IPMI/BMC 体系结构：BMC 通过板级总线采集硬件信息，对外提供 RMCP+ 网络接口，对内通过 KCS/BT 与主机 OS 通信

1.2 核心名词速查

名词全称说明
BMCBaseboard Management Controller基板管理控制器，IPMI 体系的核心芯片，独立于主机运行
IPMBIntelligent Platform Management Bus基于 I²C 的板级管理总线，连接 BMC 与各卫星控制器
KCS / BT / SSIF—BMC 与主机 CPU 之间的本地通信接口；Linux 下由 ipmi_si 驱动提供 /dev/ipmi0
RMCP / RMCP+Remote Management Control ProtocolIPMI 网络协议，走 UDP 623；RMCP+ 是 IPMI 2.0 的加密增强版（对应 lanplus 接口）
NC-SINetwork Controller Sideband InterfaceBMC 复用主机网卡对外通信的技术，即"共享网口"模式
SDRSensor Data Record传感器数据记录：BMC 里每个传感器的静态描述（类型、阈值、单位、换算公式）
FRUField Replaceable Unit现场可更换单元的 EEPROM 信息：厂商、型号、序列号、生产日期
SELSystem Event Log系统事件日志，BMC 持久化存储的硬件事件（过温、掉电、风扇失效…）
PEFPlatform Event Filtering平台事件过滤：定义"某类事件发生时执行什么动作"（告警/断电/复位）
PETPlatform Event Trap平台事件陷阱，事件触发时向管理站发送 SNMP Trap
SOLSerial Over LAN串口重定向：把主板串口（BIOS/内核 Console）透传到网络
DCMIData Center Manageability Interface面向数据中心的精简子集，主打功耗读取与功耗封顶
HPMPICMG HPM.1标准化的固件在线升级协议
ME / PSFP / CPLD—Intel ME、固件安全等周边部件，部分厂商允许经 IPMI 升级
Channel—通道：BMC 上每类通信介质的编号（Channel 1 通常是第一个 LAN 口，0 是 IPMB）
NetFn / CmdNetwork Function / CommandIPMI 报文的二级寻址：功能域 + 命令号，raw 命令的基础

02安装与内核准备

2.1 各发行版安装

# RHEL / CentOS / Rocky / Alma
yum install -y ipmitool          # 或 dnf install -y ipmitool

# Debian / Ubuntu
apt-get update && apt-get install -y ipmitool

# openSUSE / SLES
zypper install -y ipmitool

# 源码编译（需要最新版本或交叉编译时）
tar xzf ipmitool-1.8.19.tar.gz && cd ipmitool-1.8.19
./configure && make -j$(nproc) && make install

2.2 本地使用必须加载内核模块

本地接口（-I open，默认）依赖 OpenIPMI 内核驱动，设备节点为 /dev/ipmi0：

# 临时加载
modprobe ipmi_devintf
modprobe ipmi_si           # KCS/BT 接口驱动，绝大多数机器需要

# 开机自动加载
echo -e "ipmi_devintf\nipmi_si" > /etc/modules-load.d/ipmi.conf

# 验证
ls -l /dev/ipmi*
crw------- 1 root root 247, 0 Oct 26 10:00 /dev/ipmi0

# 自检：能读到 BMC 信息即正常
ipmitool bmc info
常见报错：Could not open device at /dev/ipmi0 → 依次检查 → 模块未加载（modprobe 补齐）→ BIOS 中 IPMI/BMC 被禁用 → 虚拟机无 BMC（VM 里只有 -I lan 远程模式可用）。
仅做远程管理时无需任何内核模块：ipmitool -I lanplus -H ... 走的是网络协议栈，普通 x86 工控机、笔记本、容器内都可以作为管理端。

03连接方式与全局选项

3.1 四种接口（-I 参数）

接口用途前提典型用法
open（默认）管理本机 BMC内核驱动 + /dev/ipmi0ipmitool power status
lan远程，IPMI 1.5 RMCP网络可达 UDP 623ipmitool -I lan -H ... （明文，不推荐）
lanplus远程，IPMI 2.0 RMCP+同上，推荐ipmitool -I lanplus -H ... -U ... -P ...
free与 freeipmi 兼容模式—极少使用

3.2 本地与远程对照

# —— 本地：什么都不用带 ——
ipmitool power status

# —— 远程：接口 + 主机 + 用户名 + 密码 ——
ipmitool -I lanplus -H 192.168.10.68 -U admin -P 'Admin@123' power status

# 非默认端口 / 指定加密套件 / 指定权限级别
ipmitool -I lanplus -H 192.168.10.68 -p 623 -C 3 -L ADMINISTRATOR -U admin -P 'xxx' sdr

# 交互式输入密码（不写进 shell 历史）
ipmitool -I lanplus -H 192.168.10.68 -U admin -a power status

# 从环境变量读密码（IPMITOOL_PASSWORD 优先于 IPMI_PASSWORD）
export IPMITOOL_PASSWORD='Admin@123'
ipmitool -I lanplus -H 192.168.10.68 -U admin -E power status

# 从密码文件读（文件第一行，权限务必 600）
ipmitool -I lanplus -H 192.168.10.68 -U admin -f /root/.ipmi-pass power status
安全红线：避免在命令行直接写 -P 密码，它会进入 shell 历史与进程列表（ps 可见）。批量脚本中优先用 -f 文件（chmod 600）或 -E 环境变量。

3.3 连接参数组合决策

场景推荐组合
本机巡检/装系统前配置ipmitool <cmd>（裸用，root 执行）
同机房批量管理-I lanplus -C 3 -f passfile
跨网段/安全性要求高-I lanplus -C 17（HMAC-SHA256 + AES-CBC-128）
老设备只支持 IPMI 1.5-I lan -A PASSWORD
SOL 串口重定向必须 -I lanplus

04电源与机箱控制（power / chassis）

4.1 电源操作六兄弟

ipmitool power status     # 查询电源状态
ipmitool power on         # 开机
ipmitool power off        # 强制断电（≈ 长按电源键 4 秒，OS 无机会善后）
ipmitool power cycle      # 断电后约 1 秒再上电（冷重启）
ipmitool power reset      # 硬复位（不断电，≈ 机箱 Reset 键）
ipmitool power soft       # ACPI 软关机（≈ 轻按电源键，OS 正常走关机流程）
ipmitool power diag       # 向 CPU 发 NMI 诊断中断（触发 kdump/蓝屏抓 dump 用）

chassis power xxx 与 power xxx 完全等价，例如 ipmitool chassis power cycle。

off / cycle / reset 的选择：排查网卡固件、BMC 异常类问题时，需要整机交流断电 60 秒以上让 Vaux 待机电源彻底释放（拔电源线或 PDU 断口），power off 只是逻辑关机，PCIe 待机供电仍在，不等于冷断电。

4.2 机箱状态总览

ipmitool chassis status
System Power         : on                  ← 当前电源状态
Power Overload       : false               ← 电源过载标志
Power Interlock      : inactive            ← 机箱开盖互锁
Main Power Fault     : false
Power Control Fault  : false
Power Restore Policy : previous            ← 断电恢复策略 ★
Last Power Event     : command             ← 上次断电原因（command/ac-failed…）
Chassis Intrusion    : inactive            ← 机箱入侵检测
Front-Panel Lockout  : inactive
Drive Fault          : false
Cooling/Fan Fault    : false
Front Panel Control  : none

4.3 断电恢复策略（机房必配）

ipmitool chassis policy always-on    # 市电恢复 → 自动开机（计算节点推荐）
ipmitool chassis policy previous     # 恢复断电前状态（默认，最稳妥）
ipmitool chassis policy always-off   # 保持关机（存储/特殊场景）
ipmitool chassis policy list         # 查看支持哪些策略

4.4 下次启动设备 bootdev（远程装系统的核心）

ipmitool chassis bootdev pxe                          # 下次从 PXE 网络启动 ★最常用
ipmitool chassis bootdev disk                         # 下次从硬盘启动
ipmitool chassis bootdev cdrom                        # 下次从光驱/虚拟介质启动
ipmitool chassis bootdev bios                         # 下次开机直接进 BIOS Setup
ipmitool chassis bootdev floppy                       # 下次从可移动介质
ipmitool chassis bootdev none                         # 清除设定

# 修饰选项 options=（可逗号叠加）
ipmitool chassis bootdev pxe options=persistent       # persistent：永久生效而非仅下次
ipmitool chassis bootdev pxe options=efiboot          # efiboot：强制 EFI 方式
ipmitool chassis bootdev bios options=verbose         # 组合示例

# 查看当前启动参数
ipmitool chassis bootparam get 5
无人值守重装系统的标准三连：bootdev pxe → power cycle → sol activate 盯着装机进度。装完如要还原默认磁盘启动，再 bootdev none（一次性设置通常自动失效）。

4.5 定位灯与其他机箱命令

ipmitool chassis identify 15       # 定位灯（UID灯）闪烁 15 秒，机柜找机器必备
ipmitool chassis identify force    # 一直闪，直到手动关闭
ipmitool chassis identify 0        # 立即关闭
ipmitool chassis restart_cause     # 上次重启原因（panic/watchdog/power-button…）
ipmitool chassis poh               # 累计通电时长 (Power-On Hours)
ipmitool chassis selftest          # 机箱自检
ipmitool chassis bootparam get 0   # 查看引导参数表（0~7）

05传感器监控（sensor / sdr）

5.1 sdr 与 sensor 的区别

命令数据来源特点
ipmitool sdrSDR Repository（传感器描述仓库）+ 实时读数信息最全，可按类型过滤，可导出缓存
ipmitool sensor同上输出更简洁，支持阈值设置，巡检最常用

5.2 日常巡检用法

ipmitool sdr                        # 列出全部传感器（名称 | 读数 | 状态）
ipmitool sdr elist                  # 扩展格式：含传感器实体 ID 与类型
ipmitool sdr elist full             # 只看 full 类型记录
ipmitool sdr type Temperature       # 只看温度
ipmitool sdr type Fan               # 只看风扇转速
ipmitool sdr type Voltage           # 只看电压
ipmitool sdr type "Power Supply"    # 只看电源模块
ipmitool sdr type list              # 列出本机全部传感器类型

ipmitool sensor                     # 同 sdr list，输出含上下限阈值列
ipmitool sensor get "CPU1 Temp"     # 单个传感器详情（含全部阈值与当前断言）

5.3 输出解读

ipmitool sdr
CPU1 Temp        | 32 degrees C      | ok        ← 正常
CPU2 Temp        | no reading        | ns        ← 单路机器无此传感器，ns=未指定
System Temp      | 28 degrees C      | ok
FAN1             | 4000 RPM          | ok
FAN4             | no reading        | ns        ← 风扇未安装
12V              | 12.10 Volts       | ok
VBAT             | 2.87 Volts        | cr        ← cr=超临界！主板电池快没电
PS1 Status       | 0x01              | ok        ← 离散型传感器，位掩码表示状态
状态列含义
ok正常
ncNon-Critical 越过非关键阈值（偏低/偏高）
crCritical 越过关键阈值，需立即处理
nrNon-Recoverable 不可恢复，硬件级故障
nsNot Specified 未安装/无读数，多数情况可忽略
na / no reading传感器存在但当前无读数（如第二电源未插）

5.4 单传感器详情与阈值修改

Status                 : ok

5.5 SDR 缓存与导出（加速远程批量采集）

# 远程跑 sdr 默认逐条查询很慢；先生成 SDR 缓存文件，之后用 -S 秒出
ipmitool -I lanplus -H 192.168.10.68 -U admin -f pass sdr dump /tmp/sdr-68.dat
ipmitool -I lanplus -H 192.168.10.68 -U admin -f pass -S /tmp/sdr-68.dat sdr
经验：机房批量采集 50 台机器温度，不用缓存要 5 分钟+，用 sdr dump + -S 后 30 秒内完成。监控脚本务必使用缓存。

06FRU 硬件清单（fru）

FRU 信息存储在板载 EEPROM 里，记录厂商、型号、序列号、生产日期等资产信息，掉电不丢失，是资产盘点的主要数据来源。

ipmitool fru                  # 列出全部 FRU 设备（ID 列表）
ipmitool fru print            # 打印所有 FRU 详细信息
ipmitool fru print 0          # 只打印 FRU 0（通常是主板）
FRU Device Description : Builtin FRU Device (ID 0)
 Chassis Type          : Rack Mount Chassis      ← 机箱类型
 Chassis Part Number   : CSE-826                 ← 机箱型号
 Chassis Serial        : C8260XXXXXX             ← 机箱序列号
 Board Mfg Date        : Mon May  6 20:31:00 2019← 主板生产日期
 Board Mfg             : Supermicro              ← 主板厂商
 Board Product         : X11DPH-T                ← 主板型号 ★
 Board Serial          : WM19XXXXXXXX            ← 主板 SN
 Product Manufacturer  : Supermicro
 Product Name          : SYS-2029U-TR4           ← 整机型号 ★
 Product Part Number   : SYS-2029U-TR4

 Product Asset Tag     : SRV-DB-001              ← 资产标签（可自定义）

6.1 FRU 读写操作

ipmitool fru read 0 /root/fru0.bin          # 导出 FRU 原始数据（备份）
ipmitool fru edit 0                          # 交互式编辑
ipmitool fru edit 0 field p 1 "SYS-2029U"    # 修改 Product 区域第 1 字段
# 区域代号: c=chassis  b=board  p=product
注意：部分厂商的 FRU 写保护需在 BIOS 或 BMC 中解锁；修改资产标签更推荐用 dcmi set_asset_tag（见第 14 章），兼容性更好。

07SEL 系统事件日志（sel）

SEL 是 BMC 的"黑匣子"：温度越限、风扇失效、电源故障、ECC 报错、机箱入侵等硬件事件都会落盘。存储空间有限（常见 3~5 千条），写满后按策略覆盖或停止记录。

7.1 查看与解读

ipmitool sel info               # 容量、使用量、上次清空时间
ipmitool sel list               # 列出全部事件
ipmitool sel elist              # 扩展格式（显示传感器名，推荐）
ipmitool sel list last 20       # 只看最近 20 条 ★日常巡检
ipmitool sel list first 10      # 最早 10 条
ipmitool sel get 0x1f4          # 按十六进制记录 ID 查看详情
   1 | 10/24/2026 | 03:12:41 | Temperature #0x30 | Upper Critical going high | Asserted
   2 | 10/24/2026 | 03:15:02 | Temperature #0x30 | Upper Critical going high | Deasserted
   3 | 10/25/2026 | 09:01:10 | Power Supply #0x71 | Failure detected | Asserted
   4 | 10/26/2026 | 11:22:00 | Event Logging #0xfe | Log Area Reset/Cleared | Asserted

列含义：记录ID | 日期 | 时间 | 传感器#编号 | 事件描述 | Asserted(发生)/Deasserted(恢复)。同一传感器先 Asserted 后 Deasserted = 故障已自愈；只有 Asserted 没有 Deasserted = 问题仍在。

7.2 备份、清空与时间

ipmitool sel save /root/sel-$(date +%F).log   # 文本备份（清空前必做！）
ipmitool sel writeraw /root/sel.bin           # 二进制导出
ipmitool sel readraw /root/sel.bin            # 二进制回读
ipmitool sel delete 1024 1052                 # 删除 ID 区间
ipmitool sel clear                            # 清空全部（厂商报修前常被要求执行）

ipmitool sel time get                         # 查看 SEL 时钟
ipmitool sel time set "10/26/2026 14:30:00"   # 手动校准（BMC 无 NTP 时常用）
经验：硬件报修标准动作 → sel save 备份 → sel clear 清空 → 跑压力/观察复现 → sel list 提取干净的新故障记录给厂商。混着旧日志的 SEL 会被厂商来回扯皮。

08用户与权限管理（user / channel）

8.1 权限级别

级别号名称能力
1CALLBACK最低，基本只能发起会话
2USER只读：看传感器、日志，不能开关机
3OPERATOR可读 + 电源控制 + 启动项，不能改用户/网络
4ADMINISTRATOR完全控制
15 / 0xFNO ACCESS禁用该通道访问

8.2 用户操作

ipmitool user list 1            # 查看 channel 1 的用户表 ★
ipmitool user summary 1         # 汇总统计
ID  Name         Callin  Link Auth  IPMI Msg   Channel Priv Limit
1                true    false      true       ADMINISTRATOR    ← 空名匿名账户！安全隐患
2   admin        false   true       true       ADMINISTRATOR
3   monitor      true    true       true       USER             ← 只读监控账户
4   operator01   true    true       true       OPERATOR
# 创建用户（找一个空 ID，通常 3~10）
ipmitool user set name 3 monitor
ipmitool user set password 3 'Mon#2026' 20     # 20=IPMI2.0 长密码；16=1.5 兼容
ipmitool user priv 3 2 1                       # ID3 在 channel1 上权限=2(USER)
ipmitool user enable 3

# 改密码 / 禁用 / 测试
ipmitool user set password 2 'NewPass#456' 20
ipmitool user disable 4
ipmitool user test 3 20 'Mon#2026'             # 验证密码是否正确（20/16 两种规格）

# 通道访问细调
ipmitool channel getaccess 1 3
ipmitool channel setaccess 1 3 callin=on ipmi=on link=on privilege=2
ipmitool channel authcap 1 4                   # 查看 channel 支持的认证类型
ipmitool channel getciphers ipmi 1             # 查看支持的加密套件
安全要点：① 很多主板出厂带匿名账户（ID1 空用户名），务必 user disable 1 或改名设密码；② 改掉 admin/ADMIN/ADMIN 之类的默认弱口令（Supermicro 历史上是 ADMIN/ADMIN，浪潮 admin/admin，华为 root/Huawei12#$，Dell root/calvin）；③ IPMI 2.0 连续输错密码会触发账户锁定（默认锁 60~600 秒），爆破防护的同时也容易被自己锁死。

10SOL 串口重定向（sol）

SOL 把主板物理串口的内容经 BMC 透传到网络——可以在办公室看到机房服务器的 BIOS POST 过程、grub 菜单、内核启动日志、OS 控制台，是远程装系统、救砖的核心手段。注意：SOL 看的是串口输出，不是显卡画面（画面要用厂商 KVM）。

11PEF 平台事件过滤（pef）

PEF 定义事件触发策略：当某传感器出事时，BMC 做什么——发 SNMP Trap(PET)、断电、复位、断电循环、OEM 动作。出厂通常已内置"温度致命 → 断电保护"等默认策略。

ipmitool pef info           # PEF 版本与全局能力
ipmitool pef capabilities   # 支持的动作与过滤器数量
ipmitool pef status         # 当前策略表状态
ipmitool pef policy         # 查看策略表（事件→动作映射）★
ipmitool pef list           # 查看事件过滤器表
 1 | 1 | 0xff | Match | pre-config | power-down | ...   ← 过滤器1命中→执行断电
 2 | 1 | 0xff | Match | pre-config | alert      | ...   ← 过滤器2命中→发 PET 告警
日常运维看懂 policy/list 输出即可，策略修改（pef set）涉及过滤器位掩码，出错会导致告警失效或误断电，生产环境改动前务必记录原值。告警链路完整验证：PEF 过滤器 → policy 动作=alert → lan alert 目标地址 → 管理站收到 SNMP Trap。

12.3 看门狗 watchdog

原理：OS 内的守护进程周期性"喂狗"（复位倒计时）；OS 挂死停止喂狗 → 倒计时归零 → BMC 执行预设动作（复位/断电/仅记录），实现无人值守自愈。

ipmitool mc watchdog get      # 查看当前配置与倒计时
ipmitool mc watchdog off      # 停止并关闭
ipmitool mc watchdog reset    # 喂狗（重置倒计时）
生产环境一般配合 openipmi 的 ipmi_watchdog 内核模块或 systemd watchdog 使用：加载 ipmi_watchdog 模块后由 systemd 自动喂狗，OS 僵死时触发自动复位。注意驱动编译/打补丁类的维护窗口期要先停喂狗，否则维护中途会被强制复位。

15固件升级（hpm / fwum）

15.1 HPM.1 标准升级（推荐，保留配置）

-L <level>会话权限级：CALLBACK/USER/OPERATOR/ADMINISTRATOR默认 ADMINISTRATOR
-A <type>lan(1.5) 认证类型：NONE/PASSWORD/MD2/MD5/OEM仅 -I lan 有效

19.1 批量电源状态巡检

#!/bin/bash
# power_check.sh —— 批量查询 BMC 电源状态，密码从文件读取
PASS=/root/.ipmi-pass          # chmod 600，内容就一行密码
USER=admin
while read -r HOST; do
  OUT=$(ipmitool -I lanplus -H "$HOST" -U $USER -f $PASS -N 3 -R 1 power status 2>&1)
  if echo "$OUT" | grep -q "Chassis Power is on"; then
    echo -e "$HOST \t → ON"
  elif echo "$OUT" | grep -q "Chassis Power is off"; then
    echo -e "$HOST \t → OFF"
  else
    echo -e "$HOST \t → UNREACHABLE: $OUT"
  fi
done < /root/bmc-hosts.txt

19.2 温度巡检 + 超阈值告警

#!/bin/bash
# temp_check.sh —— 采集 CPU 温度，超 80°C 告警（配合 SDR 缓存加速）
THRESH=80
HOST=192.168.10.68
ipmitool -I lanplus -H $HOST -U admin -f /root/.ipmi-pass -S /tmp/sdr-$HOST.dat \
  sdr type Temperature 2>/dev/null | while IFS='|' read -r name val stat; do
  read -r num unit <<< "$val"
  if [[ "$unit" == "degrees" && "${num%%.*}" -ge $THRESH ]]; then
    echo "ALERT → $HOST $name = $num°C ≥ ${THRESH}°C" | \
      mail -s "[IPMI] 高温告警 $HOST" ops@example.com
  fi
done

#!/bin/bash

19.4 批量资产采集（FRU + 功耗）

#!/bin/bash
# asset_collect.sh —— 生成 CSV：IP,厂商,型号,SN,BMC固件,实时功率
echo "IP,Vendor,Model,Serial,BMC_FW,Power_W" > assets.csv
while read -r HOST; do
  I="ipmitool -I lanplus -H $HOST -U admin -f /root/.ipmi-pass -N 3 -R 1"
  VENDOR=$($I fru print 0 2>/dev/null | awk -F': ' '/Product Manufacturer/{print $2;exit}')
  MODEL=$($I fru print 0 2>/dev/null | awk -F': ' '/Product Name/{print $2;exit}')
  SN=$($I fru print 0 2>/dev/null | awk -F': ' '/Product Serial/{print $2;exit}')
  FW=$($I bmc info 2>/dev/null | awk -F': ' '/Firmware Revision/{print $2;exit}')
  PWR=$($I dcmi power reading 2>/dev/null | awk -F': ' '/Instantaneous/{gsub(/ Watts/,"",$2);print $2;exit}')
  echo "$HOST,$VENDOR,$MODEL,$SN,$FW,$PWR" >> assets.csv
done < /root/bmc-hosts.txt

20故障排查与踩坑

20.1 常见报错对照

报错信息原因 → 处理
Could not open device at /dev/ipmi0 or /dev/ipmi/0: No such file本地驱动未加载 → modprobe ipmi_devintf ipmi_si；虚拟机无 BMC 属正常
Unable to establish LAN session网络不通 → ping BMC IP → 查 UDP 623 是否被防火墙拦 → 确认 lan print 中的 IP 未变
Unable to establish IPMI v2 / RMCP+ session用户名/密码错 → 用户权限不足 → 加密套件不匹配（试 -C 3/-C 17）→ 账户被锁定（等待 User Lockout Interval 或本地改密）
Get Auth Capabilities errorBMC 固件 bug 或对端不是 IPMI 服务 → 确认端口 623 上是 BMC 而非其他服务
Error loading interface lanplus发行版的 ipmitool 编译时裁掉了该接口 → 装完整包或源码编译
Authentication type NONE not supportedBMC 禁用了 NONE 认证 → 正常提供 -U/-P 即可
Insufficient privilege level当前用户权限不够执行该命令 → 换 ADMIN 用户或 user priv 提权
SOL 连上但黑屏无输出串口选错（ttyS0/ttyS1）→ 波特率两端不一致 → BIOS 串口重定向未开 → 先按回车唤醒 getty
sensor 读数全 na / no readingBMC 与传感器通信异常 → mc reset cold → 整机断电 60s → 怀疑主板硬件
LAN session timeout 偶发BMC 负载高或网络抖动 → 加大 -N 10 -R 3；批量脚本串行执行避免并发打爆 BMC

20.2 分级排错流程

# 第 1 层：本地链路
ls /dev/ipmi0 && ipmitool bmc info            → 通：本机链路 OK / 不通：查驱动与 BIOS 开关

# 第 2 层：网络可达性
ping <BMC_IP> && nc -uvz <BMC_IP> 623         → UDP 623 可达性（nc 对 UDP 仅供参考）

# 第 3 层：协议握手（开调试看细节）
ipmitool -vvv -I lanplus -H <BMC_IP> -U admin -a bmc info
→ -vvv 会打印完整 RMCP+ 握手过程，卡在哪一步一目了然

# 第 4 层：BMC 自救
ipmitool mc reset cold                        → 等待 90 秒后重连
# 仍无效 → 整机交流断电 60 秒（放掉 Vaux 待机电源）→ 再上电

20.3 实战踩坑记录

坑 1 · 批量脚本把 BMC 打挂：50 台机器并发 sdr 全量拉取，低端 BMC 直接会话耗尽 → 解决：串行执行 + -S sdr缓存 + -N 5 -R 2，或改用 ipmi_exporter 的慢轮询。
坑 2 · power off 不等于冷断电：排查网卡/BMC 固件级故障时，power off 后 Vaux 仍供电，固件状态被"冻存" → 必须拔电源线/PDU 断口 60 秒以上才算真正冷启动。
坑 3 · 账户被自己锁死：监控脚本里密码写错后高频重试，触发 Bad Password Threshold（默认 3 次锁 600 秒），连正确密码都进不去 → 等待锁定期过，或在本机用 open 接口 user set password 重置。
坑 4 · SOL 中文乱码：OS 控制台输出 UTF-8 中文经 SOL 到终端出现方块 → 把 BIOS 串口重定向终端类型设为 VT-UTF8，终端模拟器也设为 UTF-8；grub 阶段保持英文菜单最稳。
坑 5 · DHCP 模式下 IP 漂移：BMC 默认 DHCP，机房交换机重启后拿到新 IP，管理端失联 → 装机时一律改静态，或在 DHCP 服务器上绑 MAC 固定分配。

21安全加固建议

IPMI 历史上出过多次严重漏洞（cipher 0 绕过、明文哈希泄露等），BMC 一旦被控等于物理接触服务器，必须当作高价值目标加固：

必做项

  • 管理网与业务网物理/VLAN 隔离，623 端口不对业务网开放
  • 修改全部默认口令（ADMIN/ADMIN、root/calvin 等）
  • 禁用匿名账户：user list 1 查 ID1，空名即匿名
  • SNMP 团体名改掉 public：lan set 1 snmp
  • 远程只用 -I lanplus，禁用弱套件，优先 -C 17
  • 最小权限：监控账户给 USER(2)，不给 ADMIN

建议项

  • BMC 固件保持更新（厂商安全公告要跟进）
  • 交换机侧 ACL 限制 623 端口源地址为运维跳板机
  • 凭据不进脚本/命令行，统一用 -f 密码文件 + 权限 600
  • 定期 session info all 审计活动会话
  • 新平台优先考虑 Redfish（HTTPS+JSON）替代 IPMI over LAN
  • 不用 SOL 时 sol set enabled false 1 关闭面
