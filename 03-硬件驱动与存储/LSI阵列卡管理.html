LSI 阵列卡管理工具

storcli64 常用命令详解 · RAID 配置与运维
本手册面向系统测试工程师，讲解 LSI（Broadcom）阵列卡官方管理工具 storcli64 的安装与常用命令：阵列状态查看、RAID 创建/删除、硬盘点灯定位、健康检查等。所有命令带一键复制，逐个解释。命令中的 c0（控制器 0）、e（背板）、s（插槽）等编号请按现场实际输出替换。

1. storcli64 安装

storcli64 是 Broadcom 提供的统固件/SAS 阵列卡命令行管理工具，比老旧的 MegaCli64 更现代且无冗余依赖。支持 Intel 与 ARM 架构，多数发行版可直接运行，功能涵盖 LED 点灯、RAID 管理、固件操作等。建议使用值与阵列卡固件匹匹配的版本：先从 Broadcom 官网（或 LSI 下载中心）下载对应安装包，再按下方任一方式安装，或以官网自带的安装脚本为准。

RPM / DEB 包安装

针对 CentOS / Ubuntu 等主流发行版，官方提供 RPM 或 DEB 包，可用系统包管理器直接安装，自动处理依赖。

bash
# CentOS / RHEL：安装 RPM 包
sudo yum install ./storcli-007.1613.0000.0000-1.noarch.rpm -y

# Ubuntu / Debian：安装 DEB 包
sudo dpkg -i ./storcli_007.1613.0000.0000_all.deb
解释：yum install ./包.rpm 安装本地 RPM；dpkg -i 安装 DEB。安装后的命令入口一般在 /opt/MegaRAID/storcli/storcli64，或直接全局命令 storcli64。

解压二进制安装

部分版本以 zip/tar 发布，解压后把 storcli64 复制到系统路径即可运行。

bash
# 解压并进入目录
unzip storcli-*.zip
cd storcli-*/
# 赋予执行权限并复制到 /usr/local/bin
chmod +x storcli64
sudo cp storcli64 /usr/local/bin/
# 验证是否可用
storcli64 version
解释：chmod +x 赋予执行权限；cp 复制到 PATH 目录后即可全局调用。若官网提供专用安装脚本（如 install.sh），直接 sudo ./install.sh 更省事。

2. 查看阵列状态

控制器总览

先用全局 show 确认能看到控制器，再逐层查物理盘、虚拟盘、背板等。默认路径可省略，直接输命令名即可。

bash
# 查看全部控制器（确认工具可用、识别到阵列卡）
storcli64 show
# 查看控制器 0 的详细信息（固件、型号、缓存策略等）
storcli64 /c0 show
# 查看控制器 0 上的虚拟盘总览
storcli64 /c0 /vshow all
解释：show 列出所有控制器；/c0 指定控制器编号（多张阵列卡时用 /c1、/c2…）；/v 表示虚拟盘（VD/逻辑卷），all 表示全部。

物理盘 / 虚拟盘 / 背板

阵列卡全部资源都可按「控制器 / 背板 / 插槽」或「控制器 / 虚拟盘」维度查看，以便定位每块物理盘与每个逻辑卷的状态。

bash
# 查看控制器 0 的所有虚拟盘（含 RAID 级别、状态、容量）
storcli64 /c0 /vall show
# 查看控制器 0 的所有物理盘（含健康状态、盘位、转速）
storcli64 /c0 /eall /sall show
# 查看所有背板/扩展面板信息
storcli64 /c0 /eall show
# 查看每块物理盘的详情（固件、序列号、温度，适合逐个排查）
storcli64 /c0 /e32 /s1 show all
解释：/eall 表示所有背板（e=enclosure），/sall 表示所有物理盘插槽（s=slot）；/e32 /s1 指定背板 32 的 1 号盘。典型可观察项：State（Onln/UGood 等）、S.M.A.R.T、Media Error Count。

RAID 级别说明

RAID类型最小盘数可用容量容错/用途
RAID 0条带化2全部无冗余，性能最优，追求速度
RAID 1镜像250%完全镜像，单盘故障不丢数据
RAID 5条带+分布式校验3(N-1)/N允许坏 1 块盘，兼顾性能与安全
RAID 10镜像+条带450%允许每组坏 1 块，高性能高可用

3. 创建与删除虚拟盘（RAID）

RAID 0 / RAID 1

创建虚拟盘的基本结构为：storcli64 /c0 add vd type=<级别> drives=盘1,盘2 ...。RAID 0 用两盘做条带，RAID 1 用两盘做镜像。

bash
# RAID 0：背板32的1、2号盘组成一条带卷
storcli64 /c0 add vd type=raid0 drives=32:1,32:2

# RAID 1：1、2号盘做镜像（默认写策略 WriteBack，条带 64K）
storcli64 /c0 add vd type=raid1 drives=32:1,32:2
解释：add vd type=raid0 创建 RAID0 虚拟盘；drives=32:1,32:2 用「背板:插槽」定位物理盘（中间无空格）。如需指定条带大小与写策略，见 3.3 参数说明。

RAID 5 / RAID 10

RAID 5 至少 3 盘、RAID 10 至少 4 盘。RAID 10 需要把磁盘成对传入，形成镜像后再条带。下面同时演示指定写策略与条带大小。

bash
# RAID 5：3 块盘（1/2/3），条带 256K，WriteBack
storcli64 /c0 add vd type=raid5 drives=32:1,32:2,32:3 \
  strip=256 wb

# RAID 10：4 块盘成对（1-2、3-4），条带 256K，WriteBack
storcli64 /c0 add vd type=raid10 drives=32:1,32:2,32:3,32:4 \
  strip=256 wb
解释：strip=256 设条带大小为 256KB；wb 启用 WriteBack 写缓存（提升性能但断电有掉缓存风险，若电池/闪存备份异常应改用 wt）。strip 与 wb/wt 均为可选参数。

创建参数详解

参数含义示例
typeRAID 级别raid0/1/5/10
drives参与磁盘（背板:插槽，逗号分隔）32:1,32:2,32:3
strip条带大小（K 为单位）strip=256
wb / wt写策略：切换 WriteBack / WriteThroughwb
ra / rw读策略：预读 / 普通读ra
direct / cachedI/O 是否绕过缓存直写盘direct

删除与清空配置

危险操作：删除虚拟盘会清空该卷全部数据且不可恢复，务必先备份。清空所有配置前请再次确认已保存必要数据。
bash
# 先查看虚拟盘编号（v0、v1...）
storcli64 /c0 /vall show
# 删除指定的虚拟盘（v0）
storcli64 /c0 /v0 delete force
# 清空控制器所有配置（恢复出厂，删除所有卷）
storcli64 /c0 delete config force
# 若需彻底重建，可先删卷再重新创建
storcli64 /c0 /vall delete force
解释：delete force 的 force 跳过确认直接执行；/c0 delete config force 一次性清除整卡配置，用于重新规划阵列。

4. 点灯定位与健康检查

硬盘点灯定位

装机/拔盘时，让指定物理盘的盘位 LED 持续闪烁，方便在机箱中准确定位。

bash
# 点亮背板32的1号盘 LED（开始闪烁定位）
storcli64 /c0/e32/s1 start locate

# 操作完成后关闭该盘 LED
storcli64 /c0/e32/s1 stop locate
解释：start locate 触发该盘 LED 常亮/闪烁定位；stop locate 关闭。机箱前端通常可看到对应盘位的指示灯亮起。

SMART 与错误计数

排查慢性故障盘时重点看两块物理盘的 SMART 状态与各类错误计数，结合命令输出判断是否该换盘。

bash
# 查看指定物理盘的详细健康信息（SMART + 错误计数）
storcli64 /c0/e32/s1 show health
storcli64 /c0/e32/s1 show all | grep -Ei "state|smart|err|temp"

# 查看所有盘的 SMART 与温度，快速筛选可疑盘
storcli64 /c0 /eall /sall show | grep -Ei "state|smart|temp"
解释：关键字段含义：State=Onln 表示在线正常，UGood 为未配置且健康，Dgd/Foreign 为降级/外来盘；SMART 为 No 表示健康，Yes 表示已触发告警；Media Error Count / Other Error Count 持续增长需警惕。

初始化与一致性检查

新建 RAID 后建议先做初始化（快速或完全），确保磁盘干净；阵列工作中可做一致性检查（CC）校验数据完整性。

bash
# 虚拟盘 v0 快速初始化
storcli64 /c0/v0 start init
# 虚拟盘 v0 完全初始化（耗时较长）
storcli64 /c0/v0 start init full
# 触发虚拟盘 v0 的一致性检查（CC）
storcli64 /c0/v0 start cc
# 查看初始化 / CC 进度及状态
storcli64 /c0 /v0 show all | grep -i "init\|% complete"
解释：start init 快速初始化（仅清管理区），init full 完全初始化整盘（清空所有数据）；start cc 启动一致性检查，用于重建后数据校验或例行巡检。进度可从 show all 的 Init 或 CC 字段查看。
