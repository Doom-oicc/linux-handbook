定制系统封装手册

Ubuntu 22.04 Desktop · RTX 5090 · NVIDIA 595.84 · CUDA Toolkit 13.4
本手册沿用你提供的绿色工作手册网页风格：左侧目录定位、章节卡片、命令一键复制、参数表格和故障速查。目标是把当前已配置的系统级软件与环境制作成通用可启动、可安装 ISO；不克隆源用户的个人数据，并重点验证 Live 用户能否在安装后正确清理。

1. 目标、模式与封装原理

目标：将当前已配置的 Ubuntu 22.04 Desktop、NVIDIA RTX 5090 驱动 595.84、CUDA Toolkit 13.4，以及系统级软件和配置封装成可启动、可安装的 ISO。目标机安装时创建自己的正式用户；不复制源系统用户的个人 Home 数据。

模式选型：Standard Live，不是 Clone

模式/命令会做什么本项目是否使用
默认：sudo eggs remaster制作通用 Live ISO；默认标准模式排除原用户的个人 Home 数据，系统级文件通常会纳入（仍受排除列表影响）。使用
--clone克隆模式，会保留用户、凭据及 /home 数据。不要使用
--crypted生成加密的 SquashFS/LUKS 镜像，当前官方文档说明仅限 Debian 系列。不需要

“全新封装”不等于只打包官方 Ubuntu 原版文件。它是基于当前正在运行的系统重新制作 Live ISO：已经装好的系统级应用和配置通常会随镜像走；原用户 Home 目录里的个人设置不会自动完整继承。

关键区别：“保留全部系统环境”与“复制原用户全部个人配置”不是同一件事。CUDA 若只在 ~/.bashrc 里配置 PATH，新建用户未必能继承；建议把所有用户都需要的环境变量放到 /etc/profile.d/。

2. 安装与核对新版引擎

确认当前版本与安装包

本手册对应你的实际流程：Ubuntu 22.04 Desktop amd64、penguins-eggs_26.10.22-1_amd64.deb、RTX 5090、NVIDIA 595.84、CUDA Toolkit 13.4。先确认版本，避免把旧版 eggs-legacy 命令与新版命令混用。

bash
cd ~
eggs version
eggs --help
eggs version 显示封装引擎版本；eggs --help 显示当前安装包实际支持的命令。版本号或参数若与本文不同，以本机 eggs --help 和 eggs remaster --help 为准。

从本地 DEB 安装新版

bash
cd ~
sudo apt update
sudo apt -s install ./penguins-eggs_26.10.22-1_amd64.deb

先进行模拟安装。确认列表没有卸载 NVIDIA 驱动、CUDA 或 Linux 内核之后，再正式执行：

bash
sudo apt install ./penguins-eggs_26.10.22-1_amd64.deb
参数解释：cd ~ 切换到当前用户主目录；sudo 以管理员权限执行；apt update 刷新软件包索引；-s 是 simulation（模拟），只演算安装计划，不实际安装；./包名.deb 表示安装当前目录里的本地 DEB 包，前缀 ./ 很重要。

关于 yq 依赖报错

你的安装遇到过 Depends: yq but it is not installable，随后安装了本地文件 yq_3.1.0-3_all.deb，并成功配置了 python3-argcomplete、python3-toml、python3-xmltodict 等依赖。若这是同一台已处理好的机器，通常不需要重复安装。只有在新环境同样缺少可安装的 yq、并且你已从可信官方包位置取得该 DEB 时，才考虑这个绕行步骤：

bash
sudo apt install ./yq_3.1.0-3_all.deb
注意：这是针对你当前依赖问题的临时绕行方法。先检查依赖和包来源；不要把整个 Debian 软件源加入 Ubuntu 22.04，也不要在没看安装计划时强制覆盖系统包。
bash
dpkg -s yq | grep -E '^(Package|Version|Status):'
yq --version
不要为了满足一个依赖就把整套 Debian 软件源添加到 Ubuntu 22.04。你这次采用的是单独的 Debian yq DEB 包方案，属于为当前安装问题采取的绕行方式，并非 Penguins’ Eggs 对任意 Ubuntu 22.04 环境的兼容保证。新机器请优先核验官方仓库与包依赖。

软件源与 Legacy 旧版共存检查

本地 DEB 安装成功后，封装本身不一定需要再次添加仓库。若尚未配置官方仓库，可按官方文档使用下列命令；若 apt update 已显示 Penguins-Eggs 官方源，则可跳过。

bash
sudo eggs tools repo add
sudo apt update

检查当前是否还装着旧版 Legacy 包：

bash
dpkg -l | grep -E 'penguins-eggs(-legacy)?|penguins-gui'
不要同时混用 eggs-legacy produce 和新版 eggs remaster。如果旧版包仍在，先模拟卸载 sudo apt -s purge penguins-eggs-legacy，检查卸载列表没有 NVIDIA、CUDA 或内核组件，再决定是否正式卸载。

3. 驱动、CUDA 与磁盘预检

封装前检查清单

先核对系统版本、内核、NVIDIA 驱动、CUDA 编译工具和剩余空间。这些命令只读，不会修改系统。

bash
cat /etc/os-release
uname -r
eggs version
nvidia-smi
nvcc --version
command -v nvcc
readlink -f "$(command -v nvcc)"
dkms status
df -h / /home

每条命令看什么

命令检查目的合格判断
cat /etc/os-release确认基础系统发行版显示 Ubuntu 22.04 / Jammy
uname -r查看当前运行内核记录实际内核版本，例如 6.8.0-40-generic
nvidia-smi验证 NVIDIA 内核驱动/用户态工具是否通信正常识别 RTX 5090，能显示驱动版本和显存信息
nvcc --version查看 CUDA Toolkit 编译器版本显示 release 13.4（你之前的输出为 V13.4.92）
command -v nvcc查找 nvcc 当前实际路径应返回可执行文件路径
readlink -f ...解析路径最终指向位置用来判断 CUDA 安装目录，不要只凭版本号推测路径
dkms status检查 DKMS 内核模块状态NVIDIA 模块应对目标内核显示 installed
df -h / /home检查系统盘和镜像工作目录所在分区余量保留充分空间给临时文件和 ISO；具体占用取决于系统大小及压缩率
驱动兼容注意：你之前显示 NVIDIA 595.84 模块针对 6.8.0-40-generic 构建。封装会包含系统文件，但这不等于模块在所有目标内核、所有 Secure Boot 设置下都能加载。必须用生成 ISO 实际启动、安装和验证。

CUDA 环境变量检查

默认标准模式不会复制源用户的完整 Home 配置。检查 CUDA 的 PATH/库路径是否只写在用户配置中：

bash
grep -nE 'CUDA|cuda|LD_LIBRARY_PATH' ~/.bashrc ~/.profile /etc/profile /etc/profile.d/*.sh 2>/dev/null
ls -ld /usr/local/cuda* 2>/dev/null

若 CUDA PATH 只写在 /home/ps/.bashrc 中，新安装账号可能没有这个设置。确认实际 CUDA 路径后，再把“所有新用户都需要”的变量放进 /etc/profile.d/cuda.sh。下面仅为示例，执行前先确认 /usr/local/cuda 确实指向你想使用的版本：

bash
sudo tee /etc/profile.d/cuda.sh >/dev/null <<'EOF'
export PATH=/usr/local/cuda/bin:$PATH
export LD_LIBRARY_PATH=/usr/local/cuda/lib64${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}
EOF
上述 CUDA 环境变量是示例模板，不是盲目复制的通用命令。若你的真实安装路径是 /usr/local/cuda-13.4 且没有 /usr/local/cuda 符号链接，应按真实目录调整。不要把无效路径写进全局环境。

4. eggs config 详细配置

打开配置界面

bash
sudo eggs config

你看到的配置界面标题为 COA CONFIG - PENGUINS-EGGS。用 ↑/↓ 选择字段；用 ←/→ 切换选项；文字字段可直接输入；按 Tab 切换 Settings / Excludes / Save 标签。

Settings 字段建议

字段建议值说明
UserliveisoISO 启动进入 Live 桌面时使用的临时用户名，不是目标机器安装后的正式用户名。自定义用户名会被新版配置传递给 Live 系统和安装器。
Password专用强密码你截图中是默认值 evolution，建议修改。不要复用源账号或生产环境密码；这只是 Live 环境密码。
AlgorithmzstdSquashFS 压缩算法。通常适合兼顾构建速度和压缩率。官方也列出 xz、lz4、gzip。
Level3zstd 压缩等级。较高等级可能增加构建时间；建议先用默认 3，除非经过测试有更明确需求。
ISO prefixubuntu2204-rtx5090-cuda134生成 ISO 文件名的自定义前缀，便于识别镜像用途和版本。它不会改变系统功能。
RAM mode option按需；可先保留 enabled控制启动菜单是否提供将 Live 系统装入内存的选项。装入 RAM 需要足够内存；内存不足时选择普通启动。
Installercalamares图形化安装器，适合让目标机器通过窗口界面安装到硬盘。krill 是文本/TUI 安装器。
为什么设置 User = liveiso？ 你旧版镜像安装后曾残留 live（UID 1000），而正式用户 ps 变成 UID 1001。新版 changelog 从 26.10.5 起说明会把自定义 Live 用户传递到系统和安装器栈，并修复孤立 live 用户相关问题；改名不是单独的清理保障，安装后仍必须验证。

保存与 Calamares

  1. 在 Settings 完成字段修改。
  2. 按 Tab 到 Excludes，审查排除列表；具体说明见下一节。
  3. 再按 Tab 到 Save，选择 Save and exit，不要选 Exit without saving。
  4. 如果界面提示 Calamares 将在保存时安装（install on save），保持联网并等待完成。
  5. 返回终端检查：command -v calamares。有路径表示命令存在；仍需确认它可实际启动、被 Eggs 配置使用。
bash
command -v calamares
eggs config

5. Excludes、个人数据与全局环境

查看当前排除列表

bash
sudo sed -n '1,240p' /etc/penguins-eggs.d/custom.exclude.list

在配置界面中，进入 Excludes 标签，选中列表后按回车可以用当前编辑器修改。官方说明：这个文件中的路径会从生成的 SquashFS 文件系统中排除；默认列表可能包括 Docker、Podman、LXC/LXD 和 Snap 等较大的环境，因此要检查它是否符合你要复制的软件清单。

哪些应该保留、哪些要排除？

类别建议理由
NVIDIA 驱动和内核模块不要主动加入排除列表；查明其实际路径否则 Live/已安装系统可能缺模块或无法运行 nvidia-smi。
CUDA Toolkit不要排除真实安装目录，例如 /usr/local/cuda-13.4这是 CUDA 编译器、头文件和库文件可能所在的位置。先用 readlink 确认真实路径。
/home/ps 个人数据默认模式下仍要确认排除行为；不要因为想保留设置而使用 --cloneSSH 私钥、浏览器档案、Shell 历史、令牌和个人文件不应分发。
固定 IP、VPN、Wi-Fi 密码分发前清理或确认脱敏防止目标机器继承源机器静态地址、网络凭据或 VPN 配置。
Snap / Docker / Podman 等只有确实需要时才修改默认排除项被排除后相应应用或容器数据可能不会进入 ISO，镜像大小也会变化。
/etc 系统配置保留需要的系统级配置，但清理含秘密的文件系统级设置通常需要继承；不要把整个 /etc 一概排除，也不要无检查地全部复制。
个人配置迁移：如果只想继承桌面主题、输入法或普通应用偏好，可以审查后迁移所需文件到 /etc/skel 作为新账户默认配置。sudo eggs tools skel 用于从当前用户配置建立 /etc/skel，但会带来复制用户设置的风险；使用前后都要检查密钥、浏览器数据、凭据和账户相关文件，不能把它当作“无条件安全复制”。

确认 CUDA 不是只配置在原用户目录

bash
grep -nE 'CUDA|cuda|LD_LIBRARY_PATH' ~/.bashrc ~/.profile 2>/dev/null
ls -l /etc/profile.d/

如果只在原用户的 .bashrc 中设置 CUDA 变量，默认标准模式不保证把该用户配置交给新账户。应该根据真实 CUDA 路径把全局变量放在 /etc/profile.d/，再用新登录 shell 验证。

6. 正式封装与命令参数详解

正式封装命令

bash
sudo eggs remaster

这是本项目建议使用的默认 Standard Live 封装命令。不加 --clone，不加 --crypted。确认配置已保存后再执行。

常用命令参数说明

参数/命令作用什么时候用
sudo eggs remaster以管理员权限根据配置创建 Live ISO。正式封装；本项目默认使用。
-w / --wizard启动交互式向导，让你选择模式和压缩选项。想在一次向导中重新确认设置时。
--clone克隆模式，保留用户、凭据和 /home。只在明确需要完整克隆源用户时使用；本项目不要用。
--crypted加密 SquashFS/LUKS 模式；当前官方文档注明限 Debian 系列，且与 --clone 互斥。本项目不需要。
--path <路径>指定工作目录；默认 /home/eggs。工作目录需放在空间充足的分区时。
-t / --target-dir <路径>把构建树和 ISO 输出重定向到外部目录/挂载盘；会在 /home/eggs 建链接。工作盘空间不足、想把输出放到数据盘时。先确认挂载成功。
--stop-after <step>调试用：到指定步骤停止并留下挂载环境。排查构建失败；正常生产封装不要用。
--debug输出处理后的 YAML/JSON 执行计划后退出，不进行完整构建。检查计划是否符合预期；它不会生成最终 ISO。
-c / --compression版本更新记录中提供直接指定 SquashFS 压缩算法的能力，具体取值与本机版本请先看 eggs remaster --help。仅在明确需要从命令行覆盖配置时使用。
--anonymous用于控制新版引入的匿名统计/遥测相关行为；具体语义以本机 eggs remaster --help 与该版本说明为准。对统计/隐私有要求时先阅读帮助和隐私说明。
本手册把常用参数整理为操作参考。不同 26.10.x 小版本的旗标会变，执行 eggs remaster --help 可获得本机真实支持列表；不要将 Legacy 的 eggs-legacy produce 参数照搬到新版。

封装前最后一遍检查

bash
eggs version
nvidia-smi
nvcc --version
dkms status
df -h / /home
sudo eggs remaster --debug

--debug 仅用于确认执行计划。检查没问题后，再单独执行不带 --debug 的正式命令：

bash
sudo eggs remaster
封装期间保持供电、联网（如果步骤需要下载引导程序）、不休眠，不要按 Ctrl+C。磁盘临时空间会随着系统规模和压缩算法变化。

7. ISO 输出、启动与安装验收

默认输出位置

默认输出位置通常是 /home/eggs/。目录中可能看到 ISO 符号链接，真实文件位于工作目录内部；因此同时检查链接和目标文件。

bash
ls -lh /home/eggs/*.iso
find /home/eggs -maxdepth 3 -type f -iname "*.iso" -printf "%p\t%k KB\n"
readlink -f /home/eggs/*.iso

若有 ISO 文件，检查文件类型、计算校验值：

bash
file /home/eggs/mnt/你的镜像文件.iso
sha256sum /home/eggs/mnt/你的镜像文件.iso
把上面命令中的“你的镜像文件.iso”替换为实际文件名。计算的 SHA-256 可以用于复制到其他机器后校验文件是否变化；它不等于验证镜像可启动。

先启动 Live，再执行硬盘安装测试

  1. 把 ISO 写入测试 U 盘，或先在虚拟机里启动；物理机测试更能验证 RTX 5090，但虚拟机通常不能验证真实 GPU 驱动。
  2. 进入 Live 桌面后检查是否能打开桌面、网络是否正常。
  3. 启动 Calamares，将系统安装到测试磁盘/测试机；注意安装界面的分区选择，错误分区会造成数据丢失。
  4. 安装后重启，从硬盘进入新系统并创建正式用户。
  5. 检查登录页面是否只显示正式账户；确认不应残留 liveiso / Live User。
  6. 检查 NVIDIA 驱动与 CUDA：运行 nvidia-smi、nvcc --version 和 dkms status。

目标系统安装后验收命令

bash
uname -r
getent passwd | awk -F: '$3 >= 1000 && $3 < 60000 {printf "%s UID=%s HOME=%s SHELL=%s\n", $1, $3, $6, $7}'
getent passwd | grep -E '^(liveiso|live):' || true
nvidia-smi
nvcc --version
dkms status
在已安装到硬盘的系统中，如果查到 `liveiso` 或 `live` 账户，说明 Live 用户可能未被清理；若它们只存在于启动 ISO 的 Live 桌面中则属于启动环境的一部分。新版本包含动态 Live User 处理和 Calamares 清理改进，但每个定制镜像都要实际验收，不能只看版本号就认定已修复。

8. 故障排查与日志

常见问题速查

现象先做什么说明
Depends: yq but it is not installable检查 dpkg -s yq、apt-cache policy yq，核对包来源。你的 Ubuntu 22.04 曾缺少可满足的 yq 依赖；这次用单独 DEB 包绕过。避免混加整套 Debian 仓库。
安装提示将卸载 NVIDIA、CUDA 或内核输入 n 取消，并保留完整输出。不要为安装封装器牺牲已配置的驱动环境。
eggs: command not found检查 dpkg -l | grep penguins-eggs 和重新打开终端后 command -v eggs。区分安装模拟（apt -s）与真正安装。
封装停住 / 构建失败不要立即清理现场；查看日志、磁盘和挂载点。先保存最后 150 行日志，再诊断。
ISO 生成，但 NVIDIA 驱动无法加载在目标系统比对 uname -r、dkms status、Secure Boot 状态。`.run` 驱动与内核模块有关；不同内核或安全启动设置可能让模块无法加载。
安装后出现第二个 Live 用户检查实际账户：getent passwd | grep -E '^(liveiso|live):'，并检查 Calamares 安装日志。本机已遇到过 Legacy 版本残留 Live User；不要未经检查就直接删除账户。
ISO 符号链接存在但文件找不到用 readlink -f 解析真实路径，查找 /home/eggs 子目录。列表里的 ISO 名称有时是链接，不一定是实际数据文件。

失败时收集日志

bash
sudo tail -n 150 /var/log/penguins-eggs.log
df -h / /home
mount | grep -E 'eggs|liveroot|squashfs'

先保存日志再清理。sudo eggs destroy 用于安全卸载构建工作区并清除临时工作目录；不要在尚未找到 ISO 或需要保留失败现场时随便执行。
