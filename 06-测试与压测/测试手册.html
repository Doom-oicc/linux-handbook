2. 时间同步（chrony）

换源、HTTPS 证书校验、日志时间戳都依赖准确的系统时间。

安装并启用

bash
# Ubuntu / Debian
sudo apt install chrony -y
sudo systemctl enable --now chrony

配置时间源

编辑配置文件：

bash
sudo nano /etc/chrony/chrony.conf

国内环境推荐使用阿里云 / 腾讯云 NTP 服务器，注释掉默认的 pool，替换为：

conf
# pool ntp.ubuntu.com iburst maxsources 4   ← 注释掉默认源
pool ntp.aliyun.com iburst
pool ntp.tencent.com iburst

重启使配置生效：

bash
sudo systemctl restart chrony

验证

bash
# 查看当前时间同步状态
chronyc tracking

# 查看已配置的时间源
chronyc sources -v
命令 chronyc tracking 会显示 System time 偏移量，单位为秒。偏移接近 0 即表示同步正常。

3. NVIDIA 显卡驱动与 CUDA 安装

先禁用开源驱动，再装闭源驱动，最后装 CUDA 工具链。

3.1 禁用 Nouveau 开源驱动

安装前首先检查是否加载了 nouveau：

bash
lsmod | grep nouveau

创建黑名单配置文件：

bash
sudo tee /etc/modprobe.d/blacklist-nouveau.conf << 'EOF'
blacklist nouveau
options nouveau modeset=0
EOF

刷新内核引导镜像并重启：

bash
sudo update-initramfs -u
sudo reboot

重启后再次执行 lsmod | grep nouveau，应无输出，说明 nouveau 已被禁用。

3.2 安装显卡驱动

bash
sudo ./NVIDIA-Linux-x86_64-595.84.run -no-x-check --dkms

3.3 安装 CUDA

bash
sudo ./cuda_13.1.1_590.48.01_linux.run --silent --toolkit --samples \
  && sudo sh -c 'VERSION=$(ls /usr/local/ | grep -E "^cuda-[0-9.]+" | cut -d- -f2 | sort -V | tail -n 1) \
  && cat >> /etc/profile << EOF
export PATH=/usr/local/cuda-$VERSION/bin${PATH:+:${PATH}}
export LD_LIBRARY_PATH=/usr/local/cuda-$VERSION/lib64${LD_LIBRARY_PATH:+:${LD_LIBRARY_PATH}}
EOF' \
  && source /etc/profile \
  && nvcc -V \
  && cd gpu-burn/ && sudo make

3.4 内核更新后重新编译驱动模块

bash
sudo dkms autoinstall
DKMS 会自动为新内核重新编译驱动模块，因此升级内核后需执行此命令，否则 nvidia-smi 可能报驱动未加载。

4. 硬盘挂载与开机自动挂载

以把新硬盘分区 /dev/sdb1 永久挂载到 /mnt/data 为例。

4.1 查看磁盘与分区

bash
# 查看所有磁盘和分区（推荐，输出直观）
lsblk

# 或查看分区详情
sudo fdisk -l

4.2 新建分区（新硬盘无分区时）

bash
sudo fdisk /dev/sdb
# 依次输入：n（新建分区）→ p（主分区）→ 回车（默认分区号）→ 回车（默认起始扇区）→ 回车（默认结束扇区）→ w（写入保存）

4.3 格式化分区

新分区必须先格式化才能挂载。文件系统常用 ext4（通用）或 xfs（大容量高并发推荐）。
bash
# 格式化为 ext4
sudo mkfs.ext4 /dev/sdb1

# 或格式化为 xfs
# sudo mkfs.xfs /dev/sdb1

4.4 创建挂载点

bash
sudo mkdir -p /mnt/data

4.5 查看分区 UUID

bash
sudo blkid /dev/sdb1

输出示例：

/dev/sdb1: UUID="a1b2c3d4-1234-5678-9abc-def012345678" TYPE="ext4"

复制其中的 UUID 值（不含引号），下一步写入 fstab 要用。

4.6 临时挂载测试

bash
sudo mount /dev/sdb1 /mnt/data
df -h /mnt/data

4.7 写入 fstab 实现开机自动挂载

编辑 /etc/fstab：

bash
sudo nano /etc/fstab

在文末另起一行，按下面的格式写入：

fstab
UUID=a1b2c3d4-1234-5678-9abc-def012345678  /mnt/data  ext4  defaults  0  0
fstab 每行 6 个字段，用空格或 Tab 分隔：
字段含义本例取值
1设备标识（UUID 或设备路径）UUID=a1b2...
2挂载点/mnt/data
3文件系统类型ext4
4挂载选项defaults
5dump 备份标志（0=不备份）0
6开机自检顺序（0=不检查）0

4.8 验证并生效

bash
# 检查 fstab 语法是否正确，无报错即挂载所有未挂载的分区
sudo mount -a

# 确认已挂载成功
df -h /mnt/data
mount -a 无输出即表示成功；如果报错，说明 fstab 写错了（常见原因：UUID 抄错、文件系统类型不符、挂载点不存在）。

4.9 卸载（可选）

bash
sudo umount /mnt/data

5. 系统压测（stress）

对 CPU / 内存 / 磁盘施加负载，暴露系统在高压下的不稳定问题。stress 只打负载，不产出报告。

5.1 常用参数

参数作用
-c N / --cpu N开 N 个进程执行 sqrt() 计算，压测 CPU
-m N / --vm N开 N 个进程执行 malloc()/free()，压测内存
--vm-bytes B每个内存进程分配 B 字节（默认 256M）
-d N / --hdd N开 N 个进程写临时文件，压测磁盘
--hdd-bytes B每个磁盘进程写入 B 字节
-i N / --io N开 N 个进程执行 sync()，压测 I/O
-t N / --timeout N压测持续时间（默认秒，可用 m/h/d 后缀）
-v / --verbose详细输出
关键点（重点辨析）：-m、-d 后面跟的都是进程个数，不是容量；每个进程占用多少由 --vm-bytes / --hdd-bytes 决定。

总占用 = 进程数 × 单进程容量。例如 -m 256 --vm-bytes 1G 表示 256 个进程 × 各 1G = 共 256G，而不是"系统有 256 个内存"。

原写法 stress -c CPU核心数 -m 内存总容量 --vm-bytes 1G 是错误的——-m 位置填了容量而不是进程数。
压测对象进程数参数容量参数总占用
CPU-c N无（CPU 无容量概念）N 核满载
内存-m N--vm-bytes BN × B
磁盘-d N--hdd-bytes BN × B

5.2 压测前先摸清机器配置

bash
nproc        # 查看 CPU 逻辑核心数
free -h      # 查看内存总量
df -h        # 查看磁盘剩余空间
压测参数要根据上面的真实数值来定，否则容易把机器压崩：
• -c 不要超过 nproc 的值
• -m × --vm-bytes 的内存总量控制在物理内存的 70%~80% 以内
• 内存总量超过物理内存会触发 swap 甚至 OOM（系统强杀进程）

5.3 CPU 压测

bash
# 打满全部 CPU 核心，压测 60 秒
stress -c $(nproc) -t 60s -v

# 或指定核心数，例如只压测 8 核
stress -c 8 -t 60s -v
$(nproc) 会自动获取当前机器 CPU 核心数，打满所有核。

配套监控：

bash
# 监控每个核心的温度（每秒刷新）
watch -n 1 sensors

# 查看 CPU / 内存实时占用
htop

5.4 内存压测

bash
# 开 4 个进程，每个分配 2G 内存，共占用约 8G，压测 60 秒
stress -m 4 --vm-bytes 2G -t 60s -v

# 例如要占满约 16G：8 个进程 × 2G
stress -m 8 --vm-bytes 2G -t 60s -v
分配内存前先确认剩余内存足够，可用 free -h 查看。分配总量超过物理内存会触发 swap 或导致 OOM。

5.5 磁盘压测

bash
# 开 2 个进程，每个写入 1G 临时文件，压测磁盘写入
stress -d 2 --hdd-bytes 1G -t 60s -v

# 大文件长时间磁盘压测：2 个进程 × 5G
stress -d 2 --hdd-bytes 5G -t 5m -v
stress 的磁盘压测是写临时文件到当前目录，压测结束后自动删除。它会占用当前目录所在分区的空间，请确保该分区有足够剩余空间（可用 df -h 查看）。

需要更精确的磁盘吞吐 / IOPS 测试，建议用 fio：

bash
# 顺序写测试
fio --name=seqwrite --rw=write --bs=1M --size=4G --numjobs=1 --direct=1 --runtime=60 --time_based

# 随机读测试
fio --name=randread --rw=randread --bs=4k --size=4G --numjobs=1 --direct=1 --runtime=60 --time_based

5.6 组合压测（CPU + 内存 + 磁盘同时）

bash
# 8 核 CPU + 2 个内存进程各 2G + 2 个磁盘进程各 1G，同时压测 2 分钟
stress -c 8 -m 2 --vm-bytes 2G -d 2 --hdd-bytes 1G -t 2m -v

逐段拆解：

参数含义效果
-c 8开 8 个进程跑 sqrt()压满 8 个 CPU 核心
-m 2开 2 个内存进程压测内存
--vm-bytes 2G每个内存进程分配 2G内存总占用 = 2 × 2G = 4G
-d 2开 2 个进程写临时文件压测磁盘写入
--hdd-bytes 1G每个磁盘进程写 1G磁盘总写入 ≈ 2G
-t 2m持续 2 分钟时间到自动停止
-v详细模式实时打印各进程状态
整条命令的意思：同时压满 8 核 CPU + 吃 4G 内存 + 写 2G 磁盘，跑 2 分钟后自动停，过程中打印细节。

换到真实机器（以 32 核 / 32G 内存为例）的组合示例：

bash
stress -c 32 -m 8 --vm-bytes 2G -d 4 --hdd-bytes 2G -t 5m -v
# CPU 32 核全满；内存 8×2G=16G（占 32G 的一半）；磁盘 4×2G=8G 写入

5.7 停止压测

bash
# 未设置 -t 时，按 Ctrl+C 停止
# 或后台残留进程用 pkill 结束
pkill stress

6. GPU 压测与监控（gpu_burn）

跑满 GPU 计算单元，观察温度、功耗与稳定性。

bash
cd gpu-burn-master/
# 压测 60 秒（参数为压测时长，单位秒）
./gpu_burn 60

配套监控：

bash
# 实时查看 GPU 温度、功耗、利用率（每秒刷新）
watch -n 1 nvidia-smi
gpu_burn 会跑满 GPU 计算单元，使温度快速上升；结束测试前请留意温度，避免长时间超温。
