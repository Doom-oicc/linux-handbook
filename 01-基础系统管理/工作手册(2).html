工作手册

CentOS / Ubuntu 基础配置 · NVIDIA 驱动 · 硬盘挂载 · 系统压测
本手册为系统测试工程师的日常操作速查：命令已按流程合并、逐条附解释，点击代码块右上角「复制」即可一键复制。涉及版本号、网卡名、UUID 等占位内容，请按现场实际值替换后再执行。

1. CentOS 7.9 基础配置

时间同步与换源

装完系统后先校时再换源：时间不对会导致 yum 报证书或元数据错误。以下命令假设你已把准备好的源文件放在 centos7/ 目录。

bash
# 1) 手动校时（替换成当前时间）
sudo date -s "2026-09-05 14:30:00"
# 2) 清空系统默认 yum 源（避免残留源干扰）
sudo rm -rf /etc/yum.repos.d/*
# 3) 拷贝准备好的国内源文件到 yum 目录
sudo cp -r centos7/* /etc/yum.repos.d/
# 4) 重建 yum 缓存（能看到新源即成功）
sudo yum makecache
命令解释：date -s 手动设置系统时间；rm -rf 清空默认源；cp -r 拷入源文件；makecache 生成软件源缓存。若机器可联网，更推荐用 chrony/ntpdate 自动同步：sudo yum install -y chrony && sudo systemctl enable --now chrony。

安装基础软件

一次性装齐压测、监控、编译、远程管理常用工具。epel-release 是 EPEL 扩展源，很多压测工具要靠它。

bash
# 1) 安装 EPEL 扩展源
sudo yum install epel-release -y
# 2) 安装常用工具（一行装完）
sudo yum install stress stress-ng lm_sensors ipmitool htop \
  make gcc gcc-c++ curl git wget ethtool vim openssh tmux parted -y
工具分类：压测 stress / stress-ng；监控 htop / lm_sensors；远程管理 openssh / ipmitool；编译 make / gcc / gcc-c++；磁盘 parted。

所有网卡开机自启

CentOS 7 用 ifcfg 文件控制网卡，默认 ONBOOT=no 导致重启后网卡不启动、没有 IP。执行一次即可把全部网卡改为开机自启。

bash
# 把所有 ifcfg 文件中 ONBOOT=no 批量替换为 yes
sed -i "s/ONBOOT=no/ONBOOT=yes/g" /etc/sysconfig/network-scripts/ifcfg-*
解释：-i 原地修改；s/旧/新/g 全局替换；ifcfg-* 匹配所有网卡配置文件（含 ifcfg-lo，替换后对 lo 无影响）。改完 sudo systemctl restart network 或重启即可生效。

2. Ubuntu 基础配置

设置 root 密码

Ubuntu 默认禁用 root 登录，按需开启（测试机常用）。

bash
# 设置 root 密码（按提示输入两次）
sudo passwd root

更换软件源并更新系统

把默认源替换为中科大 USTC 镜像，然后刷新索引并升级系统，国内下载速度快很多。

bash
# 1) 把默认 archive.ubuntu.com 源替换为中科大镜像
sudo sed -i "s@//.*archive.ubuntu.com@//mirrors.ustc.edu.cn@g" /etc/apt/sources.list
# 2) 刷新软件索引 + 升级所有软件包（合并执行）
sudo apt update && sudo apt dist-upgrade
解释：sed -i 原地替换；@...@ 是分隔符，避免和路径里的 / 冲突；apt update 刷新索引，dist-upgrade 升级系统内核与依赖。也可用 mirrors.aliyun.com / mirrors.tuna.tsinghua.edu.cn 替换。

安装基础软件

一行装齐压测、磁盘、网络、编译等测试常用工具。

bash
# Ubuntu 基础工具全家桶（续行符 \ 表示换行继续）
sudo apt install vim ssh dkms ipmitool htop lm-sensors make gcc g++ \
  curl wget git stress stress-ng net-tools ethtool btop tmux \
  fio iperf3 memtester smartmontools nvme-cli -y
重点工具：dkms（内核模块自动重编译，装驱动必装）、fio（磁盘性能压测）、iperf3（网络带宽测试）、smartmontools（硬盘健康检测）、nvme-cli（NVMe SSD 管理）、memtester（内存检测）。

网卡自动获取 IP（Netplan）

Ubuntu 18.04+ 用 Netplan 管理网络。若网卡没自动拿到 IP，按以下步骤检查并配置。

bash
# 1) 查看所有网卡及其 IP 状态（找没有 IP 的网卡名）
ip addr show
# 2) 查看已有 Netplan 配置文件
ls /etc/netplan/
# 3) 编辑配置文件（以 00-installer-config.yaml 为例）
sudo nano /etc/netplan/00-installer-config.yaml
yaml
# 在文件里加入以下内容（eno1 换成你的实际网卡名）
network:
  version: 2
  renderer: networkd
  ethernets:
    eno1:
      dhcp4: true
bash
# 4) 应用配置（无报错即生效，网卡会拿到 DHCP 地址）
sudo netplan apply
# 5) 确认 IP 是否获取成功
ip addr show eno1
解释：dhcp4: true 表示 IPv4 自动获取地址；改完必须 netplan apply。若提示语法错误，检查缩进（必须用空格、层级对齐）。

3. NVIDIA 驱动与 CUDA 安装

禁用 Nouveau 开源驱动

NVIDIA 闭源驱动与 Nouveau 冲突，安装前必须先禁用并重启，否则驱动装不上。

bash
# 1) 检查是否加载了 nouveau（有输出=未禁用）
lsmod | grep nouveau
# 2) 写入黑名单配置文件
sudo tee /etc/modprobe.d/blacklist-nouveau.conf << 'EOF'
blacklist nouveau
options nouveau modeset=0
EOF
# 3) 刷新内核引导镜像并重启
sudo update-initramfs -u
sudo reboot
# 4) 重启后再次检查（无输出=禁用成功）
lsmod | grep nouveau
解释：tee 把内容写入文件；blacklist 禁止加载模块，modeset=0 关闭内核模式设置；update-initramfs -u 重新生成引导镜像。

安装 CUDA 并配置环境变量

用官方 .run 包安装 CUDA 工具包，随后自动检测版本写入环境变量文件（登录自动加载），最后验证编译工具链。

bash
# 1) 安装 CUDA 工具包（--silent 静默安装，--toolkit 只装工具包）
sudo sh ./cuda_13.2.1_595.58.03_linux.run --silent --toolkit
# 2) 自动检测已安装的 CUDA 版本
CUDA_VER=$(ls /usr/local/ | grep -E "^cuda-[0-9.]+" | cut -d- -f2 | sort -V | tail -n 1)
# 3) 写入环境变量文件（/etc/profile.d/ 下文件登录时自动加载）
sudo tee /etc/profile.d/cuda.sh > /dev/null <<EOF
export PATH=/usr/local/cuda-$CUDA_VER/bin${PATH:+:${PATH}}
export LD_LIBRARY_PATH=/usr/local/cuda-$CUDA_VER/lib64${LD_LIBRARY_PATH:+:${LD_LIBRARY_PATH}}
EOF
# 4) 当前会话立即生效并验证（能显示版本号即成功）
source /etc/profile.d/cuda.sh
nvcc -V
解释：CUDA_VER 自动取已装版本号，避免写死；/etc/profile.d/cuda.sh 让所有新登录会话自动加载 PATH；nvcc -V 验证 CUDA 编译器可用。${PATH:+:${PATH}} 表示在原 PATH 后追加，不影响已有路径。

编译 GPU 压测工具 gpu_burn

gpu-burn 是常用 NVIDIA 显卡烤机工具，源码目录里 make 编译即可生成 gpu_burn 可执行文件。

bash
# 进入源码目录并编译（需先解压 gpu-burn-master.zip）
cd gpu-burn/ && sudo make

4. 硬盘挂载与开机自动挂载

fstab 永久挂载

把数据盘（如 /dev/sdb1）永久挂载到 /mnt/sda，重启不失效。用 UUID 而不是设备名，避免盘符变化导致挂载失败。

bash
# 1) 创建挂载点
sudo mkdir -p /mnt/sda
# 2) 查看分区 UUID（复制输出中的 UUID 值）
sudo blkid /dev/sdb1
# 3) 编辑 fstab，在末尾追加一行（格式见下）
sudo nano /etc/fstab
text
# fstab 追加行：UUID  挂载点  文件系统  选项  转储  自检
UUID=a1b2c3d4-1234-5678-9abc-def012345678  /mnt/sda  ntfs  defaults  0  0
bash
# 4) 验证 fstab 语法并挂载所有未挂载分区（无报错=成功）
sudo mount -a
df -h /mnt/sda
# 5) 卸载（可选，临时解挂用）
# sudo umount /mnt/sda
解释：mount -a 按 fstab 逐条挂载并校验语法，是修改 fstab 后必做的验证步骤；df -h 确认挂载成功。示例文件系统是 ntfs（Windows 盘），Linux 数据盘常用 ext4 / xfs。
字段含义本例
1设备标识（UUID 最稳）UUID=a1b2...
2挂载点/mnt/sda
3文件系统类型ntfs
4挂载选项defaults
5是否 dump 备份0
6开机自检顺序0

5. 系统压测与监控

压测前检查系统资源

压测前先确认 CPU 核数、内存和磁盘余量，避免压测把机器打崩。

bash
# CPU 逻辑核数（决定 -c 用多大）
nproc
# 内存总量与可用量（G 为单位）
free -h
# 磁盘剩余空间（压测要留足余量）
df -h

CPU / 内存 / 磁盘压测（stress）

stress 常用参数：-c CPU 压测进程数；-m 内存压测进程数，总内存占用 = 进程数 × --vm-bytes；-d 磁盘压测进程数，总磁盘占用 = 进程数 × --hdd-bytes；-t 时长；-v 详细输出。

bash
# 通用模板
stress -c CPU核心数 -m 内存进程数 --vm-bytes 1G -d 磁盘进程数 --hdd-bytes 1G -t 时长 -v

# 组合示例：8 核 CPU + 2 个内存进程各 1G + 2 个磁盘进程各 1G，压测 2 分钟
# 总内存占用 = 2 × 1G = 2G；总磁盘占用 = 2 × 1G = 2G
stress -c 8 -m 2 --vm-bytes 1G -d 2 --hdd-bytes 1G -t 2m -v
注意：-m 2 是2 个内存进程，不是 2G 内存！--vm-bytes 才是单个进程占用的内存大小。CPU 压测进程数不要超过 nproc，总内存建议控制在物理内存 70%~80%，避免 OOM 把系统打死。
参数含义注意
-c N启动 N 个 CPU 压测进程N ≤ nproc
-m N启动 N 个内存压测进程总占用 = N × --vm-bytes
--vm-bytes S每个内存进程占用大小如 1G / 512M
-d N启动 N 个磁盘压测进程总占用 = N × --hdd-bytes
--hdd-bytes S每个磁盘进程写入大小如 1G
-t 2m压测时长（2 分钟）可 10s / 1h
-v详细输出方便观察进度

监控 CPU 温度与资源占用

压测时另开终端实时监控：sensors 看 CPU/主板温度，htop 交互式查看 CPU/内存占用。

bash
# 每 1 秒刷新一次 CPU 温度
watch -n 1 sensors
# 交互式资源占用面板（按 q 退出）
htop

GPU 压测（gpu_burn）

gpu-burn-master.zip 需先解压，make 编译生成 gpu_burn，然后指定秒数运行烤机。

bash
# 1) 解压源码包
unzip gpu-burn-master.zip
# 2) 进入目录
cd gpu-burn-master/
# 3) 编译生成 gpu_burn 可执行文件
make
# 4) 压测 600 秒（10 分钟），全程满载显卡
./gpu_burn 600

监控显卡状态

压测时另开终端用 nvidia-smi 监控，重点看温度、功耗、显存占用和利用率是否打满。

bash
# 每 1 秒刷新一次显卡状态（温度/功耗/显存/利用率）
watch -n 1 nvidia-smi
