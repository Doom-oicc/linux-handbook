网卡安装教程

Solarflare X2522（CentOS / Ubuntu）· Mellanox MLNX_OFED
本教程面向系统测试工程师：涵盖 Solarflare X2522 网卡在 CentOS 7.9 与 Ubuntu 22.04 下的驱动/固件安装，以及 Mellanox（MLNX_OFED） 网卡驱动的安装与模式切换。所有命令均带一键复制，逐个解释。涉及包名、网卡名等占位内容请按现场实际值替换。

1. X2522 安装（CentOS 7.9）

安装软件包

Solarflare 网卡的基础工具集 sfutils 必须安装；onload 是用户态加速协议栈，onload-kmod 是其配套内核模块（按内核版本编译）。官方下载地址：AMD Solarflare 驱动下载。

软件包作用必要性
sfutils基础管理工具集：固件升级 sfupdate、启动 ROM sfboot、许可 sfkey、诊断 sfctool必须
onload内核旁路用户态协议栈，大幅降低延迟、提升吞吐按需（高要求才需）
onload-kmod配合 Onload 的内核模块，按系统内核版本编译（3.10.0-1160.el7）与 onload 同装
bash
# 1) 安装 sfutils 基础工具集（先装）
yum install ./sfutils-8.3.3.1000-1.x86_64.rpm -y
# 2) 安装 onload 用户态加速库
yum install ./onload-8.1.3.40-1.el7.x86_64.rpm -y
# 3) 安装 onload-kmod 内核模块（与 onload 版本匹配）
yum install ./onload-kmod-3.10.0-1160.el7-8.1.3.40-1.el7.x86_64.rpm -y
解释：yum install ./包名.rpm 安装本地 RPM，-y 自动确认。三个包按顺序安装。重要：onload-kmod 版本绑定内核，若更换内核需重新下载匹配版本。

更新网卡固件

固件更新会短暂禁用目标网口，请在业务空闲时执行。命令会列出每个端口当前版本与目标版本，确认后输入 y 回车开始更新。更新过程中会有 Erasing / Writing / Complete 的进度输出。

bash
# 执行固件更新（会显示当前版本与目标版本）
sfupdate --write
text
# 典型输出：出现 "press Y then Enter" 时输入 y 回车
AMD Solarflare firmware update utility [v8.3.3]
enp225s0f0: updating Bundle firmware from 8.0.1.1002 to 8.6.2.1000
enp225s0f0: will be disabled during Bundle firmware update
To continue, press Y then Enter
y
enp225s0f0: writing Bundle firmware
[100%] Writing   [100%] Complete
enp225s0f1: not changing Bundle firmware (already 8.6.2.1000)
注意：若某端口显示 not changing ... to ...，说明它已是目标版本，无需更新。更新过程中网口会临时断开，远程 SSH 可能中断，建议走带外（IPMI/BMC）操作。

加载并验证 Onload

X2522 使用 sfc 驱动，加载 Onload 内核模块最直接的方式是用 onload_tool reload，然后验证模块是否就位、接口状态是否正常。

bash
# 1) 加载 Onload 内核模块
sudo onload_tool reload
# 2) 验证 Onload 是否可用（无报错即可）
onload
# 3) 查看详细接口状态
sfboot
# 4) 或查看当前固件/状态（不带 --write）
sfupdate
解释：onload_tool reload 重新加载内核模块；onload 单独运行会输出 Onload 版本及可用接口；sfboot 查看接口模式与 PXE/引导 ROM 设置；sfupdate（不带 --write）只查询状态、不修改。

2. X2522 安装（Ubuntu 22.04）

安装软件包

Ubuntu 下对应三个 Deb 包：sfutils（基础工具集）、onload-user（用户态加速库）、onload-dkms（内核模块，由 DKMS 在新内核下自动重编译）。

软件包作用必要性
sfutils基础管理工具集（sfupdate / sfkey / sfctool / sfboot），与 CentOS 版一致必须
onload-user用户态加速库，拦截网络系统调用实现内核旁路，降低延迟按需
onload-dkms内核模块源码，DKMS 自动为当前/新内核编译必须与 onload-user 同装
bash
# 1) 安装 sfutils 基础工具集
sudo dpkg -i sfutils_8.3.3.1000-2_amd64.deb
# 2) 安装 onload 用户态库与内核模块（用 apt 自动处理依赖）
sudo apt install ./onload-user_9.1.1.66-1_amd64.deb
sudo apt install ./onload-dkms_9.1.1.66-1_all.deb
解释：dpkg -i 直接安装单个 Deb 包；apt install ./包 会自动解析并补齐依赖，推荐用于 onload 系列。onload-dkms 利用 DKMS，内核升级后模块自动重编译，不必手动重装。

更新网卡固件

与 CentOS 流程一致，使用 sfupdate --write，确认后输入 y 回车，期间对应网口短暂禁用。

bash
# 执行固件更新（提示 "press Y then Enter" 时输入 y 回车）
sfupdate --write
text
AMD Solarflare firmware update utility [v8.3.3]
enp225s0f0: updating Bundle firmware from 8.0.1.1002 to 8.6.2.1000
To continue, press Y then Enter
y
enp225s0f0: writing Bundle firmware
[100%] Erasing   [100%] Writing   [100%] Complete

加载并验证 Onload

加载内核模块并验证 Onload 及接口状态，步骤与 CentOS 相同。

bash
# 1) 加载 Onload 内核模块
sudo onload_tool reload
# 2) 验证 Onload 可用
sudo onload
# 3) 查看接口状态
sfboot
# 查看当前固件/状态
sfupdate

其他发行版：源码编译

非 CentOS/Ubuntu 或上述 RPM/Deb 不适配时，改用官方源码包编译安装：到官网下载区 Software and Downloads → Onload & ef_vi，下载源码包后本地编译。

bash
# 官方下载地址（Onload & ef_vi 源码）
https://www.amd.com/en/support/downloads/solarflare-downloads.html/ethernet-adapters/solarflare/x2-series.html
# 解压后按 README 编译安装
tar -zxvf onload-*.tar.gz
cd onload-*/
sudo ./install

3. Mellanox MLNX_OFED 安装

下载与解压

Mellanox 网卡使用官方 MLNX_OFED 驱动。到官网按系统版本与架构下载：NVIDIA MLNX_OFED 下载页。下载后解压。

bash
# 1) 解压安装包
tar -zxvf MLNX_OFED_LINUX-*.tgz
cd MLNX_OFED_LINUX-*
# 2) 确认当前内核版本与支持矩阵
uname -r
安装前务必确认：先用 uname -r 查内核，再与安装包文档/支持矩阵比对，确认其支持当前发行版、架构、内核。不要盲目加 --force——它可能替换发行版自带 mlx5/rdma 包并掩盖依赖问题，仅在厂商明确建议且有回滚方案时使用。

安装（参数说明）

标准安装默认保留发行版自带 mlx5/rdma 驱动，只有确有功能/厂商支持需求时才安装 OFED。常用参数见下表。

参数说明
--add-kernel-support添加当前内核支持（编译内核模块）
--all安装所有组件
--force强制安装；仅在厂商建议、已备份有回滚时用
--without-fw-update不更新固件
--with-mft同时安装 MFT 工具
--vma安装 VMA 加速库
--dpdk安装 DPDK 支持
--upstream-libs使用上游库
bash
# 查看安装帮助（确认当前环境支持的参数）
./mlnxofedinstall --help | less
# 标准安装（推荐）
sudo ./mlnxofedinstall

重启与验证安装

安装完成后重启 OFED 服务（或直接重启系统），然后用 ofed_info、ibstat、ibstatus 等验证驱动、RDMA 设备与端口状态。

bash
# 重启 OFED 服务
sudo /etc/init.d/openibd restart
# 或直接重启系统（推荐）
# sudo reboot
# 查看 OFED 版本
ofed_info -s
# 查看所有组件完整版本
ofed_info -a
# 查看内核模块是否加载
lsmod | grep mlx5
# 查看 RDMA 设备与网卡映射
ibdev2netdev
# 查看网卡状态
ibstat
# 查看 RDMA 设备详细信息（端口/速率/MTU）
ibv_devinfo
# 查看网口信息
sudo lshw -class network -short
# 查看固件版本
mlxfwmanager
# 查看 HCA 端口状态（State 应为 Active）
ibstatus
解释：ofed_info -s 输出 OFED 版本（形如 MLNX_OFED_LINUX-24.10-4.1.4.0）；ibstat/ibstatus 查看端口状态，正常应为 State: Active、SM lid 有值。若 State: Down 或 SM lid: 0x0，说明缺少子网管理器（需启用 OpenSM），见安装笔记对应章节。

网口消失修复

安装后若网口不见，通常是内核模块未加载，重新加载或手动 modprobe 即可恢复。

bash
# 1) 重新加载驱动
sudo /etc/init.d/openibd restart
# 2) 或手动加载核心模块
sudo modprobe mlx5_core
sudo modprobe mlx5_ib

网卡模式切换（IB/Eth）

Mellanox 端口支持 InfiniBand 与 Ethernet 两种模式。先启动 MST、用 mlxconfig 查询并设置 LINK_TYPE（1=IB，2=Ethernet），重启生效。

bash
# 1) 启动 MST 服务（管理工具依赖）
sudo mst start
# 2) 查看设备列表，记下设备路径（如 /dev/mst/mt4119_pciconf0）
sudo mst status
# 3) 查询当前端口模式
sudo mlxconfig -d /dev/mst/mt4119_pciconf0 query | grep LINK_TYPE
# 4) 切换到 Ethernet 模式（1=IB，2=Eth）；双口网卡同时设 P1/P2
sudo mlxconfig -y -d /dev/mst/mt4119_pciconf0 set LINK_TYPE_P1=2 LINK_TYPE_P2=2
# 5) 重启生效
sudo reboot
bash
# 重启后验证模式切换结果
ibstat | grep "Link layer"
# 应显示：Link layer: Ethernet
解释：mst start/status 生成并列出设备节点；mlxconfig query 查询配置，set 写入配置（-y 跳过确认）；reboot 后模式生效。双口卡务必同时设置 LINK_TYPE_P1 与 LINK_TYPE_P2。
